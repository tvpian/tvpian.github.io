How can autonomous followers coordinate with a leader while retaining an explicit mechanism to engage, disengage, stop, and recover?

Auto-Platoon is a bio-inspired leader-follower system built around software latching. Detection, feature tracking, monocular depth, Kalman state estimation, obstacle sensing, communication, and low-level motion are connected through explicit operational states rather than an unstructured chain of model outputs.

System architecture

A latch sits between confidence and motion.

Perception proposes the leader state; the software latch decides whether the follower may continue. Dynamic obstacles and tracking loss can disengage motion, propagate stop state, and allow recovery when the operating conditions return.

Development stages

Build the safety state into the behavior.

The project connects learned perception to explicit coordination logic and physical motion.

  1. 01

    Identify the leader

    A custom object detector localizes the leader robot. Appearance embeddings help maintain identity after the initial detection.

  2. 02

    Estimate motion and distance

    Feature tracking and a Kalman filter stabilize the target state, while monocular depth supplies a distance signal for maintaining the following interval.

  3. 03

    Make engagement explicit

    The software latch records whether the follower is permitted to move. Loss of a valid target or a detected obstacle changes the state rather than silently propagating uncertain estimates.

  4. 04

    Coordinate the group

    Leader and follower processes exchange status so a local hazard can stop the platoon and allow motion to resume once the obstacle clears and tracking is restored.

  5. 05

    Test on physical robots

    The system was demonstrated with a leader, follower, dynamic obstacle, stop transition, and resumption after recovery.

I co-developed the system architecture and implementation connecting perception, state estimation, communication, software latching, and physical leader-follower behavior.

The work was completed by a four-person team. This page reports the system-level contribution without presenting the shared codebase as an individual implementation.

Interpretation boundary. A successful demonstration establishes integration feasibility. It does not by itself establish reliability at fleet scale or under adversarial communication conditions.
